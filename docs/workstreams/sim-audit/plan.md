# Plan: the full scenario audit

> Written after the audit report was reviewed and the decisions in [spec.md](spec.md) agreed (2026-10-01). One PR per row, in order, from branch `sim-audit` (PR A) and one branch per fix PR; each stops for the project owner's review.

## Approach

Every gap in [report.md](report.md) has a named case in `cases/` with the rules it breaks. `test/audit.test.ts` replays every case each run: a gap still open must keep breaking its rules (so the monitor keeps catching it), and a fixed one must not break them again. A fix PR flips its cases to `"expect": "passes"`, re-runs the fuzz runner and updates the report. Fixes are general rules, never special cases.

## Risks

- **Director-off runs will change** in B to F (they fix behaviour on calm days). Each PR re-records the fixture on purpose, with the reason.
- **The tuning rules** (docs/12) were tuned against the behaviour being fixed; some may become unnecessary or harmful. Re-run `tuning-review` in C and F.
- **Same-sex care and escalation** add staff the rota doesn't plan; watch the floating carer's and main-building carer's time on site.
- **Not a clinical tool:** the care rules follow published guidance (report.md, Sources); a registered nurse or care manager should review them before any real-world use.
